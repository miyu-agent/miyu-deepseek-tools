# DeepSeek Toolkit (deepseek-tools)

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

DeepSeek Toolkit is an extension package for Miyu that connects the [DeepSeek API](https://api-docs.deepseek.com) and the DeepSeek status page to Miyu. Once it is installed, you can use the following features:

- **Status**: the AI can use the `deepseek_status` tool to check the official DeepSeek status page (<https://status.deepseek.com/>) and see whether each service is working right now, the uptime over the last 30 days, and the incidents that are in progress or happened recently. This feature does not need a key. Because it is written in Rust, you do not need to install Python on Windows either.
- **Balance**: the AI can use the `deepseek_balance` tool to check whether your DeepSeek account can call the API, and the total balance, granted balance and topped-up balance in each currency.
- **Speech synthesis**: this package can serve as the engine for read-aloud (`say`). In the read-aloud settings, set `Engine` to `DeepSeek Toolkit`, and read-aloud then uses DeepSeek's speech synthesis. Two voices are available: `stella` (Stella, female, the default) and `tide` (Tide, male).
- **Speech recognition**: this package can serve as the engine for voice input (`voice-input`). In the voice input settings, set `Engine` to `DeepSeek Toolkit`, and voice input then uses DeepSeek's speech recognition, so you do not need to download the 163 MB local recognition model.
- **Text recognition (OCR)**: the AI can use the `deepseek_ocr` tool to recognize the text in PDF, Word (DOC, DOCX), PowerPoint (PPT, PPTX) and image files, and the results come back page by page.

To install and use it:

```sh
miyu pkg install deepseek-tools
miyu deepseek-tools               # shows whether the key is set, and the usage
miyu deepseek-tools ocr 合同.pdf   # recognizes the text in a file from the command line
miyu deepseek-tools ocr 海报.png --layout
```

> **Your files and voice are uploaded to DeepSeek and charged at DeepSeek's prices.** Speech synthesis is charged by the number of characters, speech recognition by duration, and text recognition by the number of pages. The first line of a text recognition result states how many pages were recognized in total.

## Set the key

This package uses the key you configured in Miyu for the DeepSeek model provider. During installation, the confirmation screen shows `This package gets your DeepSeek key`, and the package receives the key only after you confirm. If you later change or delete this key, the core pushes the change to the package, and the package switches to the new key. This key is only ever sent to `https://api.deepseek.com`.

If you have not configured a key yet:

- Speech synthesis and speech recognition do not work. The engine options for read-aloud and voice input still list `DeepSeek Toolkit`, but it is marked `Not running`;
- `deepseek_balance` and `deepseek_ocr` reply `No DeepSeek key yet…` and send no requests;
- `deepseek_status` does not need a key and works as usual.

> For development, you can use two test environment variables: `MIYU_DEEPSEEK_TEST_KEY` sets the key, and `MIYU_DEEPSEEK_TEST_BASE_URL` sets the API address (`https://api.deepseek.com` when it is not set). When a test key is set, the package uses the test key first. The test address applies only to the test key, so it cannot change where your own key is sent.

## How it works

This section is for developers who want to understand or change this package.

- **Speech synthesis**: calls `POST /v1/tools/tts` and asks for WAV. Because DeepSeek offers only WAV and raw PCM, the package returns WAV even when read-aloud asks for MP3, and labels it truthfully as `audio/wav`. DeepSeek does not support changing the speed, so the `speed` parameter it receives has no effect. The audio is received while it is being synthesized, and the length in the WAV header is rewritten before the audio is returned; if the transfer breaks off partway, the synthesis counts as failed.
- **Speech recognition**: calls `POST /v1/tools/asr` and uploads with the multipart `file` field. DeepSeek accepts at most 8 MiB and 120 seconds of audio at a time, so recordings longer than 110 seconds are cut into several pieces along audio frames, each piece is recognized, and the texts are then joined.
- **Text recognition**: calls `POST /v1/tools/ocr` and uploads with the multipart `purpose` and `file` fields. Files can be at most 100 MiB; the package checks the size before uploading and sends the file while reading it; if the file gets shorter during the upload, the recognition counts as failed. The text DeepSeek returns contains location markers (`<｜ref｜>`, `<｜box｜>` and coordinates); the text given to the AI has these markers removed, and the raw answer is kept in full in `data` for scripts. The `ocr` method used by the command line only accepts commands you run in a terminal, and other extension packages cannot call it.
- **Balance**: calls `GET /user/balance` (this address is not under `/v1`), and the raw answer is kept in `data`.
- **Status**: reads the <https://status.deepseek.com/> page and parses the service status, uptime and incidents from the page's Next.js data section. `tests/fixtures/status/` holds a real copy of the page and the matching standard output, and the tests compare them character by character.
- **Errors**: when something fails, the package gives a one-sentence English explanation based on the status codes in DeepSeek's documentation, followed by the original text DeepSeek returned. The key is only put in the request headers, and it never appears in errors or logs.
- **Proxy**: network connections use the system proxy settings (`HTTPS_PROXY`, `NO_PROXY`).

## Development

You can use the following commands when developing this package:

```sh
cargo test --workspace   # the tests start a fake DeepSeek service on this machine and do not connect to the real DeepSeek
cargo xtask licenses     # checks that the third-party licenses are compatible and that THIRD-PARTY-LICENSES.txt is up to date
cargo xtask notices      # regenerates the license list after upgrading dependencies
```

To release a new version, make the tag `v<version>`, and CI builds one `.miyu` package for each of the three systems (see `.github/workflows/release.yml`).
